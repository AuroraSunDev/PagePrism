# 页棱镜 PagePrism · 词典架构草案

版本：0.1；日期：2026-10-22；状态：文档与数据样例，待评审。

## 1. 词典在产品里解决什么问题

用户已经看见喜欢的网页，却难以说清动作、条件和参数。词典应帮助他指认原站片段、理解术语、修改要求，并检查 Agent 交付结果。

主路径沿用项目已确认的流程：

**输入网址 → 左侧拆解说明、右侧原站片段 → 点击术语解释 → 选择效果 → 先问网站用途，再问偏好 → 实现建议与 Agent 任务说明。**

资源提供了三类互补内容：动效词典帮助拆分动作；交互手册补充组件、状态和工作流程；视觉词典补充布局、页面结构和风格。为项目重新整理后，应让这些内容相互关联。

成功标准是：用户能把「就是这种感觉」转成包含目标、触发、变化、结束、适配和验收的要求。能否减少返工与 token 消耗，仍需实际任务验证。

## 2. 两套目录，各有用途

### 2.1 来源目录

保留三大来源及其 3／10／2 个子页；手册保留原章号 1—100。原来的编号在十个部分之间交错，不能按连续区间重排来源。视觉词典上下篇分别从 1 编到 40，必须带页面前缀。

来源目录方便回查出处、补内容和更新。它不直接决定产品的全部分类。

### 2.2 产品主题目录

| 主题 ID | 中文入口 | 收纳内容 |
| --- | --- | --- |
| structure | 页面结构与布局 | 单页／多页、首屏、案例页、Bento、分屏、瀑布流、Grid／Flex。 |
| style | 视觉风格与材质 | 极简、杂志、瑞士风、玻璃、双色、噪点、深色主题。 |
| motion | 动效与触发 | 显现、文字、滚动、指针、转场、时长与缓动。 |
| component | 组件与导航 | 表单、浮层、卡片、表格、Tabs、步骤、分页。 |
| workspace | 工具与工作流程 | 搜索、拖拽、编辑器、文件、画布、命令、历史、版本、协作。 |
| data | 数据展示 | 看板、图表、实时数据、地图。 |
| ai | AI 与 Agent 交互 | 流式输出、执行状态、上下文、引用、工具调用、人工确认。 |
| state | 状态与恢复 | 加载、空、失败、重试、权限、状态机、边界。 |
| device | 设备与输入 | 响应式、容器、视口、手势、键盘、剪贴板、媒体。 |
| quality | 体验规则与验收 | 无障碍、国际化、性能、焦点、减少动态、验收。 |

一个词条可出现在多个主题中。例如 Drawer 同时属于组件、移动适配和焦点管理；它仍然只有一个通用定义。

## 3. 主题之外，还要标明词条是什么

主题回答「在哪里找」，类型回答「它是什么」。这两个字段独立。

| kind | 解释 | 例子 |
| --- | --- | --- |
| concept | 基础概念 | UI、UX、Affordance |
| structure | 页面级信息组织 | Landing Page、Case Study、Hero |
| layout | 空间排列方式 | Bento、Masonry、Split Screen |
| style | 外观处理 | Editorial、Glassmorphism |
| trigger | 动作或状态变化的起点 | Hover、In View、Scroll-linked、Load |
| effect | 可观察的视觉变化 | Fade、Tilt、Parallax、Shared Element |
| component | 交互单元 | Tooltip、Modal、Table、Carousel |
| state | 某一时刻的状态 | Loading、Empty、Dirty、Conflict |
| workflow | 多步骤行为或交互策略 | Upload、Approval、Optimistic UI |
| parameter | 可配置的量或映射 | Duration、Easing、Stagger |
| technique | 实现方法 | FLIP、CSS Grid、Virtualization |
| tool | 库、平台能力或 API | GSAP、Motion、Three.js、View Transitions API |
| rule | 适配、质量或验收约束 | Reduced Motion、Focus Restore、Performance Budget |

每个定义选一个主要类型，用关联说明其他含义。来源将几个概念合写的情况，允许拆成多个定义。例如「Dropdown／Tooltip／Popover」拆开，另用「浮层定位」主题连接；「Focus」拆为键盘焦点与视觉注意力。

## 4. 六类数据对象

### 4.1 Term：通用词条

词条只放可复用知识，不包含某个用户的主题色或某个网站的测量结果。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| id | 是 | 稳定 ASCII 标识，如 effect.parallax；不以中文名称作主键。 |
| name.zh / name.en | 是 | 中英名称。 |
| aliases / plainQueries | 是 | 别名、初学者说法；可为空数组。 |
| kind / domains | 是 | 主要类型与多个主题。 |
| summary | 是 | 一句话白话解释。 |
| mechanism | 是 | 专业解释，说明动作或工作过程。 |
| distinctions | 是 | 易混点、非同义边界；可为空数组。 |
| relations | 是 | 指向其他词条的有类型关系。 |
| parameters | 是 | 参数名、单位、含义；没有则为空数组。 |
| rules | 是 | 适配与验收约束；有前提时写清前提。 |
| sources | 是 | sourceId、locator 或 locatorId、用途；支持同一术语多个出处。 |
| editorialStatus | 是 | draft／reviewed／published；本次样例为 draft。 |

建议的关系：`related_to`、`variant_of`、`contrasts_with`、`triggered_by`、`composes_with`、`constrained_by`、`can_use`。关系目标必须存在；别名不能代替有区别的概念。

长解释、实现提示、原创静态示意和演示链接可在正式扩写时添加。动态演示并非词条必填项；原站片段属于具体观察记录。

### 4.2 Recipe：组合配方

一个效果往往需要多个术语才能描述。Recipe 用词条拼成可参数化的要求：

`目标 + 触发 + 起始状态 + 变化 + 参数 + 结束／退出 + 重复规则 + 设备与减动替代 + 验收`。

例如「卡片依次浮现」由 In View、Fade、Slide、Stagger 组合。配方保存参数槽与约束；本次项目的实际取值放在选择记录中，避免为每种颜色、时长创建新词条。

### 4.3 Observation：某个原站的观察实例

| 字段组 | 内容 |
| --- | --- |
| 来源 | 页面 URL、采集时间、页面区域定位描述。 |
| 条件 | 浏览器／引擎及版本、视口、输入方式、减动偏好、访问前提。 |
| 证据 | 原站片段 ID、时间区间、动作序列、截图或读取的页面信息。 |
| 观察 | 谁在何时怎样变化；可测量值带测量方法和误差说明。 |
| 术语关联 | termId、解释关联理由、confirmed／candidate。 |
| 实现建议 | 候选方法、理由、限制，与观察事实分开。 |
| 覆盖情况 | 实际尝试了哪些动作；哪些状态未测、不可访问或失败。 |

每条断言分别标记 `observed`、`inferred` 或 `unknown`，不要给整篇报告一个模糊的置信分数。若没有校准依据，用明确状态和证据理由，比随意输出“93% 可靠”更合适。

**浏览器中看到了效果，不等于知道它用了哪个库。** 视频也不能单独证明屏幕阅读器、真实服务端结果、快捷键或多用户冲突处理正确。

### 4.4 Selection：用户选择与改造要求

包含 observationId、是否选择、目标页面／区域、用户用途、文字与素材、风格和颜色、参数覆盖、设备要求、保留／改变的行为。

选择全部效果不会自动意味着全部适合。对滚动锁定冲突、重复动画、过长等待、同一组件多个互斥状态，提出具体冲突并让用户调整。

### 4.5 Brief：Agent 任务说明

只引用已选实例与必要词条，包含用户目标、实现范围、逐项要求、候选技术、未知项和验收。每条验收可回溯至 selection、recipe 或 rule。

### 4.6 Source：知识来源

保存标题、URL、阅读日期、章节定位、阅读方法、阅读完成状态，以及复用权限是否确认。内容来自哪篇与某个效果在哪个网站被观察到，是两套不同来源。

## 5. 报告中的术语弹层

桌面建议使用点击打开的 Popover；长解释可以展开为侧面板。手机可用底部面板。短 Tooltip 可以补一句定义，完整词典含链接和按钮时需要可交互容器。

弹层信息顺序：

1. **名字与白话解释**：「视差：几层画面移动的速度不同，看起来有深度。」
2. **对应当前片段的位置**：「00:02—00:05，背景图相对前景标题移动得更慢。」该句来自 Observation。
3. **为什么用了这个术语**：展示关联理由；未确认时标成候选，并可纠正。
4. **怎么描述给 Agent**：调用配方，显示本次选择的参数。
5. **易混词与适配提醒**：比如进入视口 vs 滚动联动、移动端／减动替代。
6. **专业解释与出处**：折叠展开，保留返回报告的阅读位置。

打开后有清晰的焦点去向，支持键盘和关闭后焦点恢复。针对模态与非模态呈现分别定义行为；不能给所有 Popover 套用焦点锁定。复杂词典弹层不依赖 hover 作为唯一入口。

## 6. 识别与检索如何使用这套词典

### 6.1 从原站到候选术语

先按区域整理观察，再沿「对象—触发—变化—结束」标注候选词。不要只给“高级感”“科技感”风格标签。

- 布局和外观：可从截图提出候选，但不能由单张截图断言响应式行为。
- 时间动效：需要连续画面，注明触发动作与重复情况。
- 加载、错误、权限、协作、AI 工具执行：没有真实证据时保留未观察状态；词典有该词不等于分析器能识别。
- Canvas／WebGL：可描述视觉变化；无法定位内部对象或确认具体实现时如实标记。

### 6.2 从用户自然语言找词

先支持中英文名、别名和白话查询匹配，再按触发、对象、主题筛选。初期用静态 JSON 和关键词索引即可评估内容；语义检索在查找失败确实频繁时再考虑。

| 用户说法 | 候选词 | 要补问的区别 |
| --- | --- | --- |
| 一张一张浮出来 | Stagger、In View、Fade、Slide | 滚到那里开始，还是一直跟着滚动走？ |
| 鼠标靠近会被吸过去 | Magnetic Button | 移动按钮本体、内部内容还是光斑？ |
| 左边不动，右边一直换 | Sticky Storytelling、Split Screen | 左侧只是固定，还是内容也随章节更新？ |
| 点图片后变成大封面 | Shared Element、Lightbox | 打开浮层，还是进入独立详情页？ |
| 灰色框在闪 | Skeleton、Shimmer | 是真实加载状态还是持续装饰？ |

保留多个候选时使用区别问题，不把含糊输入悄悄确定成单一效果。

## 7. 参数需要标明出处与状态

同一个 duration 值可能是原站估测、用户选择、配方建议，或项目现有规范。用 `basis` 区分：`measured`／`user`／`suggested`／`project-token`，附单位与来源。

原文含若干时长、幅度、断点和性能预算例子，只能作为作者建议或具体提示词中的例值。不要写成全平台标准，不要用假进度补齐未知任务进度。

参数例：durationMs、delayMs、staggerMs、translatePx、scaleRatio、rotateDeg、triggerThreshold、repeatMode、scrollRange、damping。没有需要时，不要求用户填写所有字段。

Spring 的时长未必与固定 duration 一一对应；Ease 的名字也不能替代具体曲线。迁移到某个库时再确认可表达的参数及单位。

## 8. 需求提问与 Agent 输出

### 提问顺序

1. 这个网站做什么、给谁看、希望访客完成什么动作？
2. 新建还是已有项目？目标页面、设备和项目技术约束是什么？
3. 确认所选效果放在哪里、保留什么、改掉什么。
4. 统一收集主题、颜色、文字、素材、节奏；只有特殊效果再单独追问。
5. 展示汇总，标出假设和未决定项，再生成交接说明。

### 建议的 Markdown 交接结构

- 项目目的与现有约束。
- 选中效果：实例 ID、来源 URL、片段与区域。
- 行为规格：触发、初始／结束状态、参数、重播与退出。
- 内容与视觉：用户确认的文案、素材、色彩和目标位置。
- 实现选项：匹配已有技术栈的简洁方案、复杂方案的代价；全部标为建议。
- 设备与无障碍：触摸、键盘、减少动态和不支持时的可用替代。
- 验收：可执行动作、应见结果、失败与边界。
- 未知项：明确下一位 Agent 要验证的事项。

不把整部词典塞入每次提示词，只展开已选配方及其必要规则。未选择的库和效果不自动成为开发需求。

## 9. 验收规则按前提挂载

| 适用前提 | 应补充的检查 |
| --- | --- |
| 可操作组件 | 鼠标、键盘、触摸能完成主要任务；Focus 可辨认。 |
| 模态对话框 | 打开焦点、背景访问限制、关闭方式、关闭后恢复焦点。 |
| 异步请求 | loading／success／error；防重复；保留输入；重试与取消是否适用。 |
| 数据列表 | 0／1／大量数据、长文本、图片失败、筛选空、返回位置。 |
| 自动／大幅动画 | 暂停入口是否需要、减少动态替代、关闭动画仍可读可用。 |
| 拖拽／手势 | 替代操作、滚动冲突、移动端点击区域、取消和边界。 |
| 路由／共享元素 | 正常导航后备、焦点、滚动位置、返回行为。 |
| AI／后台任务 | 准备与执行区别、停止／失败／部分结果、是否等待用户确认。 |

词典可以提出验收要求；只有测试记录才能表明实现已通过。自动化浏览器引擎的记录与真实 Safari／具体手机设备测试分别保存，浏览器支持信息应随实现阶段更新。

## 10. 内容维护与后续开发边界

### 本次可用资产

- 来源全集、原章号和主题映射已在 catalogue.json 保留。
- 详细样例展示定义、关联、规则、来源和组合方式。
- 虚构的端到端数据展示报告怎样引用词典，没有把它当成真实网站分析结果。

### 扩写顺序

先把用户最常看见的布局、触发、显现、滚动、指针、浮层和基础反馈扩成完整词条；再沿目录扩展复杂工具、数据和 AI 交互。目录完整与产品识别能力完整分别跟踪。

正式发布每批词条前检查：定义准确、别名不过度合并、关系可解析、来源可回查、参数有单位与依据、配方含退出和适配、示例标明真假、必要时核实官方技术资料。

### 存储建议

概念验证阶段维护版本化 JSON 与 Markdown 足够。未来应用读取词条、来源、配方和规则；用户项目单独存观察与选择。等协作编辑、历史或数据规模形成明确需求后再选数据库。

原站片段的存储与授权、任意 URL 的隔离、采集覆盖、模型选择、具体前后端实现均属于后续设计。词典不会自动解决网页拆解，也不证明任意网站的全部效果都可被采集。

## 11. 一条从白话到任务说明的示例

以下为虚构的结构示例，没有对应真实采集片段。

用户说：「我想让我的课程作品卡片像参考一样，一张张浮上来。」

### 术语卡片示例

| 词条 | 给初学者的解释 | 专业边界 |
| --- | --- | --- |
| 进入视口 In View | 滚到看见这个区域时，动画才开始。 | 动画一旦开始可以按时间继续；不一定随滚动进度停走。 |
| 淡入 Fade | 从透明变成清楚可见。 | 透明度不自动决定能否点击或获得焦点。 |
| 位移 Slide | 从稍低的位置移动到排版中的正常位置。 | 不需要改变最终布局；方向和距离要明确。 |
| 交错 Stagger | 每张卡片比上一张晚一点开始。 | 是开始时间的间隔，与单张卡片的动画时长不同。 |

### 在报告中怎样解释

「这组卡片进入可见区域后依次显现；每张同时发生淡入与向上位移。停止滚动后动画仍继续，因此目前更接近进入视口后播放，而非滚动联动。原站采用的库与精确参数仍未知。」

真实使用时，这段话必须引用原站片段和动作记录；没有证据时只能展示为待验证的候选解释。

### 经过用途与偏好确认后的交接草案

目标：个人作品集首页展示课程项目，让招聘者进入项目详情。

- 位置：精选项目区，使用用户提供的真实封面和文案。
- 行为：首次进入视口后，卡片按顺序淡入并从下方轻微上移到正常位置。
- 参数：单张 360ms、相邻开始间隔 70ms、向上回位 12px、只播放一次。全部为示例选值，需确认。
- 结束：卡片保持完整显示，快速滚过也不能遗留隐藏内容。
- 适配：减少动态时直接显示；键盘访问项目链接时保持内容可见、焦点清晰。
- 候选实现：优先沿用已有项目能力；是否使用 CSS、视口观察或动画库，在了解技术栈后决定。
- 验收：慢滚、快滚、返回该区、键盘访问及减少动态偏好分别检查。
- 尚缺：真实片段、现有项目结构、触发阈值、最终素材与文案。

机器可读的对应关系见 dictionary-examples.json 中的 recipe、observation、selection 与 brief。这里的建议值不会写回通用术语定义。
