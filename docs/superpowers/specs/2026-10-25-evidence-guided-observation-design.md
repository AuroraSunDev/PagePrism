# 证据驱动的观察与交接

## 目标与授权
用户要求按 Web-Design-System-Skill 的分析结果完善 PagePrism，延续通用识别和轻量产品边界。本轮实现覆盖缺口驱动的补查、可追溯的多参与者交互说明，以及可复现的质量对照。保留原站片段作为可靠对照。

## 方案选择
- 采用：在现有本地 Playwright 引擎增加有限观察策略、结构化交互记录与评测器。复用现有工作台、词典、导出与安全层。
- 后续评估：模型根据证据进行语义分析；需要明确调用成本、运行环境和增益，本轮不接模型服务。
- 后续验证：选中效果的参数化演示；待识别质量有依据后推进。本轮不建设完整设计系统站、跨页爬虫或自动复原。
上述取舍为实现方依据用户已批准优先级作出的范围裁定，不伪称用户逐项指定技术。

## 行为与契约
### 覆盖与补查
每个被发现的代表性交互有结构化记录：触发类型、目标、检查状态（待查／已查／受阻／预算停止）、观察结果（变化／未见变化／关系待确认）、已观察状态、尝试次数、原因和关联条目。检查完成不等于已证明因果关系。
先检查尚未观察的家族，再补查无变化或存在干扰的目标。最多8组代表悬停，另允许最多2次同组补查、每组最多2次尝试。已读取的 CSS 时长／延迟用于决定有限驻留时长；没有时长证据的补查采用1500ms观察窗口。每次驻留最多2000ms。所有动作仍在12条、120秒总预算内。
动作失败标为受阻并继续；待查目标在停止时标明预算限制，不宣称没有效果。保持滚动后重新发现、容器滚动、独立展示入口和取消保护。

### 交互说明
Finding 增加可选 behavior：参与者（主体／子元素／伪元素／邻近浮层）、各参与者发生变化的属性与首次采样时间、默认／动作中／动作后画面引用、恢复情况、参数来源与未知项。仅描述同一次观察中可见的组合，不推断完整编排、设计意图或使用的库。
比较保留中间状态，滤除同一参与者在静止阶段已有的自主变化；其他元素的真实反馈不被一并删去。CSS声明参数与画面测量分开：默认0s不当作脚本动画的真实时长。未确认的时长、缓动、循环和减少动态支持明确未知。
ReportRun.coverage 增加可选 checks；旧报告和 Finding 保持可读，原始事实不被用户修改覆盖。报告和 Agent brief 使用同一 behavior 生成组合说明与验收步骤；只导出选中效果的行为记录。现有观察范围折叠区显示覆盖结果，详情区增加简洁交互过程，不新增页面。

## 质量评测
建设独立的8个行为对照样例，包含声明延迟、脚本延迟、多元素组合、邻近自主文字干扰、后续区域和静态／自主变化反例。金标由样例实际行为定义，匹配触发、目标和属性，不依赖生成标题。对相同 URL 和预算运行冻结基线0b2480d与候选，报告关键行为覆盖、已确认悬停误报、状态／组合信息完整度与耗时。基线无此类结构化说明时记为不支持，不将格式新增当成识别准确率。
这些合成对照是机制验证，不称为陌生真实网站或用户重要性金标。另复核公开参考页；如公网受限如实记录，不外推跨站准确率。评测器可以承接之后人工标注的真实站点集合。

## 安全与范围
不新增依赖或模型费用。网络代理、私网检查、GET/HEAD限制、入口的表单／条款／导航排除、后续主页面导航阻断均保持。补查只移动指针，不增加点击范围。独立分支工作，保存用户现有数据。

## 验收
延迟目标在相同总预算内得到有效证据；静止状态中的自主文字不吞掉真实提示，也不被确认为悬停。多参与者说明可追溯到原帧，未知参数不填造；旧报告和导出仍工作。完整测试、安全回归、跨浏览器主流程及一次独立审查通过；评测如实展示增益和未改善项。
