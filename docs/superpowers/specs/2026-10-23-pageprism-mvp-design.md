# 页棱镜 PagePrism · 产品方案与 MVP Scope

日期：2026-10-23。由“暂不实施”进入本轮用户授权的设计与搭建阶段。技术与范围选择由实现方提出；不伪称已由用户逐项选择。实现与测试结果另行记录。

后续修订：视觉采集的当前范围以[通用视觉观察改进](2026-10-23-general-motion-observation.md)为准（12条、8组、120秒及保守入口探索）。下文保留初版设计基线。

## 1. 产品定位

帮助学习 Web 开发的学生和创作者，把参考网页中喜欢的布局、视觉与交互，转成自己看得懂、能选择、能交给 Coding Agent 的要求。

核心交付是参考到交接的工作台。成功的一次使用：输入公开网址，查看自动发现的区域与效果，播放真实原站片段，点击术语理解含义，选中部分效果，说明用途与偏好，导出可验证的 Agent brief。

## 2. Approaches 与本轮选择

| 方案 | 取舍 |
| --- | --- |
| A：本地 Web 工作台＋真实采集＋规则解释 | 首次运行要准备 Chromium；无账号、模型费用和云存储依赖，能验证完整价值路径。本轮推荐并按用户授权采用。 |
| B：云端 SaaS＋多模态模型＋后台队列 | 更适合远程共享和复杂语义，但引入费用、密钥、部署隔离和多用户数据边界，留作后续。 |
| C：浏览器扩展＋手动录制 | 可进入当前登录页，但有安装和浏览器差异，也不能代替用户要求的输入网址自动发现，暂不采用。 |

参考责任：designlang 为产品参考；Design MD Extractor 为技术结构参考；Motion Capture 为动效表达参考；已有词典为知识内容基础。核对记录见 ../../research/2026-10-23-references.md。

## 3. 第一版包含

### 输入与采集

- 普通 Web 界面，中文优先。默认本地服务绑定 127.0.0.1；用户可用主流浏览器打开，无需扩展。
- 输入一个 HTTP／HTTPS 公开页面 URL；不递归爬站，不访问用户已有浏览器会话。
- 后端用独立 Chromium 上下文采集，桌面 1440×900；另在 390×844 检查页面结构与截取移动端画面。
- 自动发现最多 6 个有代表性的区域／组件。基础层包括首屏、布局、排版与色彩；动效层执行加载、受控滚动、最多 3 个悬停目标。
- 每个报告条目保留动作、视口、来源 URL、截图、样式证据；存在动作过程时关联原站视频区间与关键帧。
- 无有效动效证据时展示静态设计观察，不强行发明动画。识别名称可为候选，用户可编辑白话说明。
- 限制单次采集总时长 90 秒；超时、局部失败保留已完成条目。当前只运行 1 个任务，取消后释放上下文。
- 不自动点击提交、购买、删除、登录等操作。第一版只执行滚动、移动指针与页面读取；可能的点击效果标为未观察。

### 阅读与理解

- 左侧条目说明与证据状态，右侧原站视频／截图；支持切换视频与关键帧。
- 关键帧保留真实采样时间，4／6／9 格展示或导出 PNG；有限帧数不足时显示实际数量，不复制画面凑数。
- 显示已观察／推测／未覆盖；精确时长只有实际读取到时才标记为测量值。
- 点击术语打开上下文解释：白话定义、当前条目为什么相关、易混词、实现建议和来源。
- 读取现有 46 个详细词条；完整来源／主题目录保留为内容索引，不将 synthetic 观察和 brief 作为真实报告种子。
- 独立词典视图支持中英名、别名与白话查询，返回报告时保留选择。

### 选择、改造与交接

- 单选、多选、全选、取消；报告中可以纠正白话描述。
- 进入改造配置时，第一项必须说明网站用途；随后填写目标区域、主题、强调色、文案、节奏与已有技术栈。
- 参数区分 measured／user／suggested／project-token。本轮主要用用户选择与明确的建议，未知保留未知。
- 输出可预览、复制、下载的 Markdown：DESIGN.md（原站设计观察）和 AGENT-BRIEF.md（仅包含选择项与改造要求），以及 evidence.json。
- 导出 brief 包含来源、触发、起止状态、用户改造、设备与减少动态规则、验收及未知项。不把候选库伪装成原站实现。

### 保存与演示

- 结果保存在本地 .pageprism/runs，每个 run 独立目录。刷新后可重新打开已完成结果；不上传云端。
- 内置一个原创参考页，用真实采集流程生成演示结果，清楚标为内置示例。不能把该结果混为用户输入站点的分析。
- 首页可“体验示例”，但真实 URL 入口是主入口。数据删除和分享不是本轮交付；README 说明本地目录位置和手动清理方式。

## 4. 本轮不包含

登录页和 Cookie 导入、跨页爬取、浏览器扩展、桌面录屏、任意文件上传、账号／计费／云同步、多人协作、自动重建网站、部署目标站、全部动效识别、3D 内部场景恢复、模型聊天和第三方模型 API。

排除项可在报告中解释限制，不能只在文档里隐藏。用户输入不可访问站点时给出明确失败信息和内置示例入口，不能返回假成功。

## 5. 页面与使用路径

1. **开始页**：页棱镜 PagePrism、短说明、网址输入、开始拆解、体验示例、最近结果。
2. **分析状态**：打开页面／观察结构／记录交互／整理报告，显示真实阶段；可取消，无虚构百分比。
3. **拆解工作台**：顶部来源和覆盖范围；左侧条目列表；中部白话说明、术语、观察证据；右侧原站片段／关键帧。底部选择数和“定制并生成”。
4. **术语解释**：点击打开可交互弹层或侧面板；手机为全宽对话区域，支持关闭与焦点恢复。
5. **需求与交接页**：用途优先的简短表单、选中效果摘要、Markdown 预览与导出。返回报告不丢选择和已填内容。
6. **词典页**：搜索与主题筛选；只展示实际拥有的定义，完整目录明确为扩写索引。

桌面优先的左右对照在窄屏改为“说明／原站画面”切换；手机仍能完成选择和导出，不强挤三个面板。

## 6. 数据与模块

延续 Term、Recipe、Observation、Selection、Brief、Source 的分离。新增 Run 管理任务与覆盖，不重写既有词典来源文件。

```
浏览器界面 → API：创建／读取／取消任务
                     ↓
URL 校验 → 隔离浏览器 → 采集原始证据与媒体
                     ↓
规则归纳 → 词典关联 → Run／Observation
                     ↓
用户 Selection → 模板生成 DESIGN／BRIEF／JSON
```

技术选择：React＋TypeScript＋Vite；Node.js＋TypeScript＋Express；Playwright Chromium；Zod；Vitest；Playwright Test。样式使用 CSS tokens，图标使用统一线性图标。初期文件存储，不引入数据库、Redis 或庞大状态管理。

API：POST /api/runs {url}、POST /api/runs/demo、GET /api/runs、GET /api/runs/:id、POST /api/runs/:id/cancel、GET /api/runs/:id/media/:file。Selection 与配置由前端保留并可导出；不在 URL 中暴露文本内容。

状态：queued → loading → observing → processing → completed／partial／failed／cancelled。采集日志显示阶段和警告，报告断言采用 observed／inferred／unknown。

## 7. URL 与内容边界

- 仅允许无凭证的 HTTP／HTTPS 地址及标准端口；拒绝 localhost、私网、链路本地、保留地址、IPv6 本地与 IPv4 映射地址等。
- 主 URL、重定向和子请求都校验目标；阻止服务工作线程、WebSocket、下载、弹窗以及写入型网络请求。
- 浏览器上下文不复用个人 Cookie，不读取本机文件；页面文字只当数据，不拼成执行指令。
- 只对内置示例与自动化测试提供固定的内部来源通道，不允许公开输入 URL 通过参数打开私网豁免。
- 路径必须按已验证 run ID 和媒体文件名读取；媒体只提供既有白名单文件，禁止任意文件访问。
- 本轮仅作为本机开发工具。应用层 URL 校验不等于生产级网络隔离，公开部署前需要容器和网络出口策略，并再次测试 DNS 重绑定与资源配额。

## 8. 质量标准

- 真实网址能生成非空报告或明确失败；实际媒体可播放／切换，关键帧时间不编造。
- 选择更改会改变 brief；未选条目不泄露到需求，缺少用途不能生成完成态。
- 词典解释可打开、关闭、检索；上下文不丢；纯键盘能走完整条路径。
- 刷新、局部失败、无动效、网络超时、取消、重复提交、长标题均有可理解结果。
- 桌面和手机无关键内容溢出；尊重 prefers-reduced-motion；界面不靠悬停才能操作。
- Chromium 自动化验证为主要运行证据；Firefox／WebKit 验证客户端流程，不能据此宣称真实 Safari 和所有手机已验证。
- 不报告没有测量的准确率、节省 token 比例、性能分数或“全部动效已识别”。

## 9. 视觉方向

“设计研究工作台”：白色画布、近黑文字、低对比细线、少量钴蓝强调。清晰的标题与紧凑工具控件形成层级，原站媒体是主要视觉焦点。使用开放行列表和一处媒体工作区，避免装饰性 Dashboard 与多层卡片。

Image Gen 用于设计概念，不用生成图片冒充原站采集。完整概念需覆盖开始、报告、交接以及移动对照状态；控件、文字、视频与词典都由真实代码实现。

## 10. 交付与推进顺序

先保存方案、参考依据、实施计划与测试范围；完成 builder check 和视觉概念；再按本轮直接搭建授权实施。

实施依次交付：证据与 URL 边界 → 真实采集与媒体 → 工作台与词典 → 配置和导出 → 端到端／跨尺寸／视觉核对。测试清单见 ../../testing/2026-10-23-mvp-test-scope.md。

完成交付包含本地可运行项目、启动说明、测试结果与已知限制。GitHub 推送、仓库改名和公开部署不在本轮授权范围中，不以本地修改声称已发布。
